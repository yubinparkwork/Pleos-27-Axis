## 레퍼런스의 해석

Instagram `DBGP-7JAckN`의 초반 약 0~3초는 검은 배경 위 두꺼운 유리의 가장자리와 내부 반사상이 움직이는 매크로 컷이다. 넓은 면은 어둡게 남고, 굴절·반사된 색띠는 곡률을 따라 압축되고 늘어난다. 4~5초에는 별도 고립된 유리 형태로 컷이 바뀐다. 원본의 조명 세팅, IOR, 렌더러는 영상만으로 확정할 수 없다.

이후 제공된 분홍빛 유리 큐브 이미지는 어두운 투명 면, 부드러운 가장자리 하이라이트와 안쪽으로 겹치는 광학 공간의 무드 레퍼런스다. 단일 큐브를 복제하는 대신 기존 Axis 세 큐브의 관계에 이 조명·반사 무드를 적용한다.

최신 분광 큐브 레퍼런스는 어두운 면 중앙, 모서리 안쪽에 나란히 나타나는 색 분산, 깊이에 따라 풀리는 반사층을 강조한다. 디멘션 레이어는 이 결을 편집할 수 있는 가상 광학 반사상 모델이다. 완전한 물리 시뮬레이션이나 참조 이미지 복제는 아니다.

구현에 레퍼런스 픽셀이나 모델을 사용하지 않는다. 원본의 반사 패턴과 실루엣이 동일하다고 주장하지 않는다. `카메라 → 확대` 또는 휠로 중앙 접점을 매크로로 볼 수 있으며, 큐브 배율과 저장된 카메라 값에 따라 외곽이 판형 밖으로 잘릴 수 있다.

## 엔진 선택

R3F는 Three.js의 장면 구성 계층으로, 그 자체가 화질 상한은 아니다. 과거 반복 반사의 제한은 화면 버퍼의 재사용과 근사 표현에서 발생했다. 새 엔진은 장면을 세 개의 닫힌 분석적 솔리드로 제한해 범용 메시 패스 트레이서 없이 직접 광선 경로를 계산한다.

`OpticalRenderer → optical.frag.glsl → OpticalResolve` 구조:

1. 정사영 카메라에서 광선을 출발시킨다.
2. AABB로 교차 구간을 제한하고 rounded-box signed distance로 실제 앞·뒷면과 베벨을 찾는다. 반복 한도에 도달한 광선은 평면·원기둥·구 패치의 해석적 교차로 해결하며, 법선 방향 오프셋으로 자기 교차를 억제한다.
3. Snell 굴절, 비편광 Fresnel 반사율, 전반사를 계산한다. `면 곡률`이 양수이면 연마 유리의 완만한 렌즈 효과를 shading normal로 근사한다. 실제 외곽과 교차 위치는 변형하지 않으며, 매질의 안/밖 판정과 광선 오프셋은 기하 법선을 사용한다.
4. 각 RGB 채널의 IOR를 다르게 한다. 실제 내부 반사는 전체 추적 한도 최대 16과 에너지 감쇠로 제한한다. 별도로 디멘션 레이어 0~12를 연속 값으로 제어한다. 0은 추가 반사상 층만 끄며 실제 유리 반사·투과는 남는다.
5. 밖으로 나온 광선은 이웃 큐브도 통과한다. 이 보조 경로는 최대 8개 경계까지만 추적하며, 이웃마다 완전한 반사 트리를 재귀적으로 계산하지는 않는다.
6. 조명은 네 방향의 부드러운 스튜디오 면광원이다. 기본 단일색에서는 하나의 `lightColor`와 강도를 모든 광원이 공유한다. 선택형 `lightCycle`은 각 방향에 공간적으로 분리된 RGB 띠 광원을 배치하고 80/10/10 광량 비중을 교대한다. sRGB 색상은 선형 광량으로 변환하고, 고정된 월드 방향의 negative-fill aperture는 일부 입사 방향을 어둡게 한다. 색은 유리 albedo가 아니라 입사 광량에 적용된다.
7. 선형 광량을 FP16(`RGBA16F`)에 유지하고 서브픽셀을 선형 공간에서 평균한다. 지원되지 않으면 `c/(1+c)`로 범위를 압축한 RGBA8 경로로 폴백하며, 정밀도는 FP16과 동등하지 않다.
8. 밝은 광량에만 유한 범위 HDR bloom을 적용한 뒤 부드러운 톤 매핑, sRGB 변환, 공간 FXAA 순서로 출력한다. 화면 피드백, 메시 발광, 무작위 그레인, 참조 이미지 합성은 없다.
9. 미리보기와 PNG 모두 판형 바깥의 guard 영역까지 계산한 후 최종 화면을 잘라낸다. 타일 사이뿐 아니라 화면 맨 가장자리에서도 bloom이 동일하게 이어진다.

WebGL2를 선택한 이유는 이 제한된 분석적 장면을 현재 브라우저에서 바로 구동하기 위해서다. 이름만 WebGPU로 바꾸거나 다른 프레임워크로 감싸는 것이 속도/화질을 보장하지는 않는다. 이 코드가 Redshift와 동등한 완전한 분광 패스 트레이서라는 의미도 아니다.

## Geometry contract

- 카메라 방향: `normalize([1, 1, 1])`, azimuth `45°`, elevation `35.264389682754654°`.
- 큐브 반변 길이: `1.6534055763786452` (기존 대비 모서리 길이 2배). `OPTICAL_CUBE_SCALE = 2`. 새 기본 장면은 전체 큐브를 보기 위한 줌을 사용하지만 기존 저장된 카메라와 간격은 자동으로 바꾸지 않는다.
- gap=0의 중심: `[-h,+h,-h]`, `[-h,-h,+h]`, `[+h,-h,-h]`.
- `getAxisCubes(gap)`는 화면의 `90° / 210° / 330°` 방향으로 동일 거리 이동한다.
- 배율1의 기본 투영은 기존 `CrystalAssembly`의 모든 sharp-cube 투영 정점과 검증했다. 현재 배율2는 원점과 축 방향을 유지하며, 기존 카메라에서는 외곽이 더 크게 잘릴 수 있다.
- 베벨은 모서리를 깎으며, 렌더 배치는 `getRenderAxisCubes(gap, bevel)`에서 자동 보정한다. 베벨에 비례해 세 중심을 같은 방사 방향으로 안쪽 이동시켜 gap=0에서 세 쌍의 곡면이 부피 중첩 없이 접한다. 양의 gap에서도 쌍별 실제 간격은 `sqrt(3) * gap`으로 베벨과 무관하다. 카메라 깊이·전체 무게중심·축 각도는 유지한다. 둥근 세 물체가 쌍별 접하는 것이며 세 곡면이 하나의 꼭짓점을 공유하는 것은 아니다.
- `surfaceCurvature`는 이 좌표·크기·간격·실루엣과 별개인 광학 법선 제어다. 0에서는 평면의 원래 법선을 사용한다. 양수의 렌즈 효과를 실제 휘어진 메시 또는 정확한 렌즈 형상으로 해석하면 안 된다.

## 조작

- 드래그: 카메라 회전. 휠/트랙패드: 커서 위치가 아닌 중앙 기준 확대. 카메라 패널의 확대 슬라이더/숫자 입력과 같은 `0.4~24×` 범위이며 기존 저장 줌은 그대로 유지한다.
- 형태: 큐브 간격과 베벨 곡률.
- 디멘션 레이어: 기본 시점의 상단·왼쪽·오른쪽 큐브 각각 0~12, 슬라이더 0.05 단위·직접 소수 입력 지원. 소수 부분은 마지막 층의 등장 강도이며 기존 층의 위치를 바꾸지 않는다. `층의 형태 조정`에 층 간격·층 풀림·깊이 감쇠가 있다. 각도·가림·흡수에 따라 일부 층이 보이지 않을 수 있다.
- 광학: IOR, 분산, 광학 확산, 면 곡률, 반사, 무채색 흡수, 전체 광선 추적 한도.
- 조명: 하나의 색상 선택기/HEX와 Pleos 스와치, 전체 강도, 폭, 노출, 빛 번짐. 번짐 0은 bloom을 끈다. 화이트 광원에서는 여러 색의 분산이 보이며, 포화된 유색 광원에서는 해당 색 계열로 제한된다. 색 분산 0이면 가상 층의 파장별 위치 차이도 꺼진다.
- `광학 → 레퍼런스 무드 적용`: 유리·조명·베벨·디멘션 표현을 변경하지만 현재 카메라, 큐브 간격, 판형은 유지한다. 최초 적용 전 설정은 localStorage의 `pleos-optical-before-luminous-v1`에 한 번 보존하며 반복 적용으로 덮어쓰지 않는다. 현재 설정 키와 달리 자동 복원되는 활성 상태는 아니며 개발/복구용 백업이다.
- 하단: 재생/정지/시간, 판형, 길이, 조명 이동폭. 속도는 재생 길이로 결정하고 이동폭은 궤도 크기를 조절한다.
- 같은 시간/설정은 같은 결과를 생성하며 한 주기 양 끝의 광원 위치가 일치한다.

## 출력과 제한

- 미리보기는 재생 중 긴 변 최대 1280px, 정지 시 최대 1920px이며 표시 크기의 1.5~2배 샘플링을 위 한도 내에서 적용한다. 4K 저장은 미리보기를 확대하지 않고 별도로 렌더링한다.
- `zoom > 2.4`에서는 위 표시 버퍼의 가로·세로 각각 2배인 광학 버퍼로 계산한 뒤 축소한다. 동일 프레임의 2×2 공간 샘플링이라 이전 모션 프레임이 잔상으로 섞이지 않는다. 고배율/높은 반사 횟수에서는 재생 속도가 낮아질 수 있다.
- 광선 교차 허용 오차는 world-space 픽셀 크기에 비례하고 `0.000002~0.00012`로 제한한다. 확대 시 고정 오프셋이 띠처럼 드러나는 문제를 줄이지만, float 정밀도와 유한 샘플링의 한계가 완전히 없어지는 것은 아니다.
- UI PNG는 긴 변3840px: 1:1=3840²,4:5=3072×3840,9:16=2160×3840,16:9=3840×2160.
- 타일당192px, UI 저장은4×4(16개) 슈퍼샘플링. 광학 버퍼를 선형 HDR에서 최종 타일 크기로 평균하고 톤 매핑한다. Canvas2D로 이미 톤 매핑된 화면을 확대/축소하지 않는다. Canvas2D는 최종 픽셀의 방향을 바로잡고 타일을 연결하는 데만 사용한다.
- 가드 밴드는 bloom의 최대 반경과 FXAA 범위를 포함한다. 반경은 전체 출력 높이/1080에 비례하며 타일 크기·서브픽셀 수와 무관하다. 출력 밖의 광량까지 계산한 후 가드를 잘라내 타일 경계에서 번짐이 끊기지 않게 한다. API 기본 샘플은4개다.
- 이 슈퍼샘플 수는 Monte Carlo 패스 트레이싱의 SPP와 다른 개념이다. 무작위 노이즈를 생성하지 않지만 유한 해상도의 아주 가는 반사선은 앨리어싱될 수 있다.
- 고정 시간의 복사본을 내보내므로 출력 도중 모션 시간이 바뀌지 않는다.
- `window.__pleosOptical.capture(width,height,samples)`는 최대8192px/34MP를 허용한다. 더 큰 출력은 명시적으로 거부한다.
- PNG는 불투명 검은 배경,8bit sRGB이다. PPI 메타데이터/인쇄판형,알파출력,MP4,시퀀스 UI는 새 엔진에 아직 없다.
- 광학 확산은 경로 깊이에 따라 넓어지는 광원 필터와 선명한 반사 성분의 감쇠이다. 흩어진 에너지를 전 방향으로 다시 적분하는 완전한 마이크로패싯 BSDF는 아니다. 면 곡률도 optical-normal 근사다. 오프라인 패스 트레이서, 초점심도, 전체 파장 스펙트럼, 바닥·체적 코스틱은 구현하지 않았다.
- 보조 광선의 재귀 깊이와 유한 반사 제한으로 일부 에너지가 잘린다. 무한한 물리 정확도를 주장하지 않는다.

## 검증과 handoff

`npm run verify`는 새 기본 앱과 geometry contract를 검증한다. 이전 전체 체인은 `npm run verify:legacy`에 보존했다. 이전 Dimention R3F의 극단 노출 stress check 실패 이력은 별개이며, 새 엔진 검증 통과를 이전 모든 모드의 무결성 통과로 해석하면 안 된다.

실제 실행한 결과는 `artifacts/optical-rebuild/qa-report.json`, 최신 생성 상태는 `artifacts/latest/runtime-state.json`에 기록된다. 완료 후 `npm run handoff:full`로 현재 기본 앱의 문서와 세 판형 이미지를 갱신한다. 자동 commit/push는 하지 않는다.

확대 전용 검증: 로컬 서버 실행 후 `node scripts/verify-optical-macro.mjs`. 별도 브라우저 컨텍스트에서 4×/12×/24× 샘플 비교, 숫자/방향키/휠 확대, 저장 복원, 좁은 패널을 검사한다. `artifacts/optical-macro/report.json`의 RMSE는 같은 엔진의 16개 서브픽셀 기준과의 차이이며 물리적으로 완벽한 정답과의 차이는 아니다.

디멘션/HDR 검증: `node scripts/verify-optical-dimensions.mjs`. 전용 Vite 서버(51743)를 실행하고 종료하며, 독립 브라우저 컨텍스트에서 큐브별 0/3/8 깊이, 곡률 변경 시 geometry 불변, UI 저장 복원, 조명 0, 루프 양 끝을 검사한다. `PLEOS_OPTICAL_URL`을 명시한 경우만 해당 서버를 재사용한다. 같은 400² 출력에서 1/2/4배 샘플의 full-frame과 가드 타일 결과도 비교한다. 결과와 정확한 경계 차이는 `artifacts/optical-refinement/dimension-verification.json`에 기록된다. 이는 4K 전체 품질이나 오프라인 물리 정답과의 비교를 대신하지 않는다.

## Soft gradient dimensions

층 간격을 넓히면 그라데이션의 축 바깥쪽 꼬리도 자동으로 넓어진다. 기준은 화면 중심이나 개별 큐브 중심이 아닌 월드 Axis 원점 `[0,0,0]`이다. 각 반사상 교차면의 접선 방향과 원점에서 멀어지는 방향을 비교해 비대칭 폭을 적용한다. 축에서 멀수록 더 풀리며, 폭 증가만큼 피크 광량을 낮추고 최대 폭을 제한한다. 최근접 모서리 방향은 부드럽게 혼합해 면 중앙의 삼각형 경계가 생기지 않게 했다. 새 조절기는 없으며 기존 큐브별 간격과 공통 층 풀림을 사용한다. 최소 간격 0.06에서는 추가 방향성 확산이 꺼진다.

층 간격은 `dimensionSpacingTop / dimensionSpacingLeft / dimensionSpacingRight`로 각각 조절한다(0.06~0.3, UI 증감 0.005). 저장값에 개별 값이 없으면 기존 `dimensionSpacing`을 이어받는다. 공통 키는 이전 API 호환용으로만 남아 `set({dimensionSpacing: …})`은 세 간격에 적용하고, 같은 patch에 명시한 개별 값이 있으면 해당 값이 우선한다. 패널에서는 세 독립 슬라이더만 표시한다. 풀림·깊이 감쇠와 기하 구조는 변경하지 않는다.

광원은 매끄러운 중심과 넓은 어깨를 가진 띠 프로파일이다. `dimensionLayers()`는 실제 외피에서 굴절된 광선을 큐브 내부의 점점 작은 가상 반사상 경계에 교차시킨다. 그 교차면의 rounded-square 윤곽과의 거리로 그라데이션을 만들고, 입사 광원·반사 방향·흡수·깊이 감쇠로 강도를 결정한다. 면 내부를 채우는 텍스처나 불투명 중첩 큐브는 없다. 광원 0이면 모든 층도 검정이다.

각 층 위치는 `extent ∝ exp(-dimensionSpacing × (order + 0.7))`, 마지막 층 활성화는 `smoothstep(0, 1, count - order)`이다. 반사상은 개별 물리 매질 경계가 아닌 아트 디렉션용 근사다. 기하 법선을 보존하는 실제 Snell/Fresnel 경로와 함께 합성되며, coherent 경로와 층의 노출 비율을 조절해 흰 반사가 색 분산을 덮지 않게 했다. 색 분산은 층 윤곽을 기준으로 파장별 위치를 분리한다. 엄밀한 분광 에너지 보존 모델은 아니다.

모션 루프는 조명 이동과 선택형 RGB 주도색 순환을 지원한다. 자동 레이어 증감 모션은 추가하지 않았지만, `set({dimensionTop: 3.25})`처럼 연속 값으로 제어할 수 있어 향후 타임라인에서 보간 가능하다. 원래 RGB 필드는 이전 JSON 호환용으로만 남아 새 셰이더에는 연결되지 않는다. 새 `lightColor`가 있으면 항상 우선한다. RGB만 있는 저장값은 한 색상으로 변환되므로 완전히 같은 구색은 보장하지 않는다. 최초 덮어쓰기 전에 원본을 `pleos-optical-before-dimension-layers-v1`에 보존하며, 백업 실패 시 원본 저장값을 덮어쓰지 않는다.

### RGB 주도색 순환

조명 패널의 `RGB 주도색 순환`을 켜면 현재 선택 색상 계열부터 **그린 → 레드 → 블루** 순서로 교대한다(시작 계열에 맞춰 순서 회전). 선택한 HEX는 그 계열에 그대로 쓰고, 나머지는 Pleos Red 2 `#FA293C`, Green 2 `#0ADC91`, Blue 3 `#2350FF` 중 해당 색을 사용한다. 유리 재질은 무채색이며 발광하지 않는다. 네 면광원 각각의 서로 떨어진 세 띠에서 반사·굴절 광선을 평가한다. 단순히 화면이나 물체 전체 색을 바꾸지 않는다.

각 주도 구간은 메인 0.8 / 서브 각각 0.1의 광원 가중치다. 가중치 총합은 전 구간 1이며, 각 구간의 35%는 유지하고 나머지 65%에서 quintic easing으로 다음 색에 넘긴다. 색마다 선형 RGB 에너지와 가시 경로가 다르므로 **밝기나 화면 점유율이 정확히 80%라는 뜻은 아니다**. 카메라·베벨·층·노출에 따라 보이는 비율이 달라진다.

전체 주기는 하단 재생 길이(기본 15초)이며 재생/정지·스크럽·PNG 출력이 같은 절대시간을 사용한다. 스위치를 켤 때 현재 시간을 정규화한 `lightCycleOffset`을 저장해 그 위치부터 선택 색이 주도한다. 기존 설정과 신규 기본값은 `lightCycle: false`로 보존된다. 스위치와 위상은 자동 저장되고 끄면 기존 단일색으로 복귀한다. 새 광학 재질, 큐브, GPU 텍스처는 추가하지 않는다.

검증: `npm run verify:optical-light-cycle`은 별도 Vite/Chrome 컨텍스트에서 비중 합, 연속성, 세 주도색 PNG, 루프 처음/끝의 byte 일치, 기존 단일색 복귀, 조명 0 검정, 키보드 스위치·현재 시점 시작·재접속 복원·좁은 패널을 확인한다. 결과는 `artifacts/optical-light-cycle/verification.json` 및 같은 폴더의 PNG다. GPU 성능이나 정확한 색 점유율을 보장하는 벤치마크는 아니다.

검증 스크립트는 2.99→3→3.01의 연속성, 각 층 제어의 이미지 변화, HEX 검증/스와치/저장, 무광원 검정, 타일 일치도도 검사한다. 새 레퍼런스 캡처는 `node scripts/capture-dimension-layers.mjs`, 3072×3840/16샘플은 `PLEOS_4K=1 node scripts/capture-dimension-layers.mjs`. 결과는 `artifacts/optical-layers/`에 기록한다.

현재 기본값은 `OpticalState.ts`, 레퍼런스 표현 패치는 `LuminousReference.ts`, 실제 사용 중인 값은 `window.__pleosOptical.inspect().state`를 기준으로 한다. 문서의 숫자를 별도 프리셋으로 취급하지 않는다. 저장된 카메라·간격·판형은 무드 적용으로 덮어쓰지 않는다. 과도한 흡수는 내부를 어둡게 하고, 거의 0인 베벨은 층을 가는 선으로 압축한다. 레퍼런스와 큐브의 형태·광학 경로가 다르므로 동일한 패턴을 보장하지 않는다.
