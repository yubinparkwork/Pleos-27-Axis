# PLEOS 27 Axis — Optical Studio

## 판형

화면 비율 메뉴는 1:1, 4:5, 9:16, 16:9, **A시리즈 · 세로**(1:√2), **3:2**(가로)를 지원한다. 선택값은 기존 자동 저장·이름별 설정에 포함되며 카메라/모션/조명 값은 변경하지 않는다. A시리즈는 공통 비율이며 A4/A3 등의 실제 인쇄 크기나 PPI 설정이 아니다.

긴 변 3840px 기준 A시리즈 PNG는 2715×3840, MP4는 인코더의 짝수 크기 조건에 맞춘 2716×3840이다(가로 1px 차이). 3:2는 PNG/MP4 모두 3840×2560. UI의 출력 크기 표시는 실제 출력 계산과 공유한다.

## 카메라 고정 · 엑시스 회전

`엑시스 회전` 패널의 모션 1은 카메라가 아니라 전체 Axis 모델과 디멘션 광장을 회전시킨다. 공유 원점은 고정하며 `입체 회전 폭`(Y축, 기본24°), `기울기 회전 폭`(공간 Z축, 기본12°), `축 이동 시간`(기본8초)을 조절한다. 25엑시스 홀드 뒤 출발해 부드럽게 회전하고 루프 끝에 원위치로 돌아온다. Axis 모션은 카메라 모션보다 우선하며 기준 카메라·pan·zoom은 변하지 않는다.

OpticalAxisMotion.ts의 강체 회전 역행렬로 카메라 광선을 모델 공간에 옮겨 실제 회전한 구조를 계산한다. 2D 화면을 돌리는 효과가 아니며, 간격·베벨·층 간 거리는 유지된다. 반사광 장은 구조와 함께 회전하고 RGB 순환·층 페이드 시간은 그대로 유지한다. 같은 행렬을 회색25Axis 전환과 PNG/MP4에도 적용한다. 큰 회전에서는 원래 3D 구조의 가림 때문에 보이는 층과 밝기가 달라질 수 있다.

현재 세팅은 `0916 · 카메라 고정 · 엑시스 회전`, 변경 전 수치는 `0916 · 엑시스 회전 적용 전`으로 로컬 이름 저장했다. 기존 카메라 모션 실행본 `saved-20260915095918835`는 보존한다.

## 25엑시스 → 디멘션 카메라 모션

카메라 패널의 `카메라 모션`을 1로 켜면 기존 기준 구도를 유지한 채 25엑시스 홀드 이후 시점만 이동한다. `수평 회전 폭`(기본 −24°), `수직 회전 폭`(+6°), `이동 시간`(8초)을 조절한다. 지정한 각도까지 부드럽게 이동한 뒤 재생 끝에 원래 카메라로 돌아온다. 시작·최대 이동·복귀 경계에는 속도와 가속도가 0인 quintic easing을 사용한다. 짧은 타임라인에서는 이동 시간을 맞춘다.

큐브/Axis/빛의 구조는 회전시키지 않는다. 저장된 수평·수직 각도는 기준값으로 남으며, pan/zoom도 유지한다. `OpticalCameraMotion.ts`의 결정적 시간 평가를 미리보기·PNG·MP4가 공통 사용한다. 이전 저장 세팅은 모션 0(고정)으로 불러온다. 현재 적용 전 코드 스냅샷은 `saved-20260915095138614`; 실제 사용자 수치는 별도 이름 `0915 · 카메라 모션 적용 전 고정 세팅`으로 보존했다. 둘 다 로컬 보관이며 GitHub 백업을 의미하지 않는다.

## 현재 표현: 디멘션 반사

현재 기본 경로 `/`는 Raw WebGL2 기반 OpticalStudio다. 자체 발광 실험을 되돌려 `saved-20260915085224893`의 **스튜디오 빛이 입체 디멘션 경계에 반사되는 표현**으로 복구했다. 큐브의 면 전체를 색칠하거나 발광 메시를 중첩하는 방식은 아니다. 25엑시스 → 디멘션 전환 중에는 기존 Axis를 따라 빛을 한 번 강조한다.

세 큐브의 배치, 공유 Axis 기준점, 카메라, 간격·베벨 보정은 유지한다. 바깥쪽으로 열린 디멘션 경계와 25엑시스 전환·층별 등장 스태거도 같은 구조를 사용한다. 반사 표현을 복구해도 기존 수치·저장 이름·카메라·출력 설정을 재설정하지 않는다.

**RGB의 주도색 순환은 시간으로 결정된다.** 카메라를 돌리면 광학 투영, 반사 방향, Fresnel, 구조의 가림·겹침이 달라져 화면에 보이는 빛도 달라질 수 있다. 특정 각도에서 색상 프리셋을 전환하는 방식은 아니며, grazing 시점의 광학 투영은 연속적으로 연결한다.

실제 사용 값은 `window.__pleosOptical.inspect().state`, 활성 표현은 `rendering.expression`과 `rendering.emission`을 확인한다. 문서의 숫자를 별도 기본 프리셋으로 취급하지 않는다.

## 현재 렌더링 구조

`OpticalRenderer → optical.frag.glsl + identity25.glsl → OpticalResolve`

1. 정사영 카메라 광선과 기존 rounded-box 경계의 교차로 세 Axis 영역을 찾는다. 외곽·가림·간격·베벨은 기존 분석적 3D 구조를 유지한다.
2. `dimensionLayers()`는 IOR와 RGB 분산을 반영한 굴절 방향을 카메라 광선에 제한적으로 혼합해 중첩된 3D 평면 경계를 찾는다. 영역별 고정 평면 법선과 grazing 완화를 사용해 윤곽의 휨·갑작스러운 투영 전환을 억제한다. 층 0은 Axis에 가장 가까운 기존 경계이며, 이후 층은 `imageExtent = half × exp(-spacing × order)`로 배치된다.
3. 경계까지의 거리로 부드러운 그라데이션과 좁은 반사광 코어를 계산한다. 최대 50겹이며, 마지막 층의 소수 부분은 `smoothstep(0, 1, count - order)`로 부드럽게 나타난다. 불투명 내부 큐브나 참조 텍스처는 추가하지 않는다.
4. 네 개의 부드러운 분석적 스튜디오 광원과 월드 공간의 negative fill을 가진 `environment()`를 반사 방향으로 평가한다. 윤곽 밴드·코어, 입사광, edge Fresnel, 깊이 흡수·감쇠를 조합한다. 물리 외피의 직접 표면 반사색은 출력에 더하지 않는다.
5. RGB별 IOR 차이로 가상 광학 이미지의 채널을 분리한다. 전체 파장 스펙트럼을 추적하는 모델은 아니다. 기존 굴절률·광학 확산·반사광 선명도·반사 강도·흡수·조명 폭·세기 컨트롤을 복구한다.
6. 선형 광량을 FP16(`RGBA16F`)에 유지하고 공간 샘플을 선형 공간에서 평균한다. 미지원 장치는 `c/(1+c)`로 범위를 압축한 RGBA8 경로를 사용한다. 정밀도는 FP16과 동등하지 않다.
7. 유한 범위 HDR bloom, 톤 매핑, sRGB 변환, 공간 AA를 적용한다. 미리보기·PNG·MP4 모두 판형 밖 guard 영역까지 계산한 뒤 잘라내므로 타일과 화면 바깥 경계의 번짐이 이어진다.

현재 모델은 아트 디렉션용 **가상 광학 반사층 렌더러**다. 유리 내부의 실제 무한 반사, 광자 추적, 바닥·체적 코스틱, Redshift와 동등한 물리 패스 트레이서를 의미하지 않는다. 무작위 시간 누적 노이즈나 레퍼런스 이미지 합성은 없다. 이전 물리 외피용 함수가 셰이더에 남아 있어도 현재 진입 경로에서 호출하지 않는 코드는 Legacy / reference only다.

## Geometry contract

- 기본 카메라: `normalize([1, 1, 1])`, azimuth `45°`, elevation `35.264389682754654°`.
- 큐브 반변 길이: `1.6534055763786452`. `OPTICAL_CUBE_SCALE = 2`이며 저장된 줌을 자동 변경하지 않는다.
- gap=0의 원래 중심: `[-h,+h,-h]`, `[-h,-h,+h]`, `[+h,-h,-h]`.
- `getAxisCubes(gap)`는 기본 화면의 `90° / 210° / 330°` 방향으로 동일 거리 이동한다.
- `getRenderAxisCubes(gap, bevel)`는 베벨에 따라 세 중심을 안쪽 보정한다. gap=0에서 세 쌍의 곡면이 부피 중첩 없이 접하며, 양의 실제 쌍별 간격은 `sqrt(3) × gap`이다.
- 카메라 깊이·전체 무게중심·축 각도는 유지한다. 둥근 물체 세 쌍의 접점이 하나의 둥근 공통 꼭짓점과 동일한 것은 아니다.
- 먼 쪽으로 열린 반사 경계는 표현용 확장이다. 브랜드의 원래 중심·축·세 큐브 관계를 대체하지 않는다.
- `surfaceCurvature`는 **반사광 선명도**다. 반사광 필터의 법선 집중도만 바꾸며, 굴절 투영·좌표·크기·간격·실루엣 같은 기하 구조를 변경하지 않는다.

`레퍼런스 무드 적용`은 기존 버튼과 패치를 유지한다. 카메라·간격·판형을 유지하고 베벨·유리·조명·반사층의 수치를 조정한다. 최초 적용 전 설정은 `pleos-optical-before-luminous-v1`에 보존한다. 이는 자동 복원되는 활성 상태가 아니라 별도 복구용 백업이다.

상단·왼쪽·오른쪽 층 간격은 `dimensionSpacingTop / dimensionSpacingLeft / dimensionSpacingRight` 각각 0.06–0.3이다. 이전 공통 키만 있는 설정은 세 영역에 이어받는다. API에서 공통 값과 개별 값을 함께 넣으면 명시한 개별 값이 우선한다.

드래그로 카메라 회전, 휠/트랙패드로 커서 위치가 아닌 중앙 기준 확대를 한다. 확대 범위는 0.4–24×다. 화면 위치·판형·수치와 이름별 저장값은 그대로 유지한다. 기본 저장 키는 `pleos-optical-studio-v1`, 25엑시스/순차 등장 경로는 기존 분리 네임스페이스를 계속 사용한다. localhost와 127.0.0.1 같은 서로 다른 origin의 localStorage는 자동 공유되지 않는다.

## 모션과 RGB 조명 순환

층의 기하 윤곽을 일렁이거나 휘게 하지 않고, 기존 경계를 따라 빛이 흐르고 전체 층이 나타났다 사라진다. 상단·하단 왼쪽·하단 오른쪽의 지연은 루프 내의 위상 이동이다. 25엑시스의 `등장 스태거`는 별개의 초 단위 시작 간격으로, 1초이면 Axis에 가까운 층부터 1초마다 시작한다. 0초는 동시 등장이다. 마지막 층이 잘리지 않도록 필요한 재생 길이를 확보한다.

`RGB 주도색 순환`은 **레드 → 그린 → 블루 → 레드**의 순서를 유지한다. 선택한 HEX는 해당 계열에 적용하고 나머지는 Pleos Red 2 `#FA293C`, Green 2 `#0ADC91`, Blue 3 `#2350FF`를 사용한다. 단일색 모드는 선택한 색상으로 돌아간다.

메인 0.8 / 서브 각각 0.1은 **기본 입사광 에너지 가중치**다. 가중치 총합은 1이며 기존 quintic 전환과 위상 앵커를 유지한다. 광원 방향, 반사/Fresnel, 깊이 감쇠, 노출, 겹침이 있으므로 밝기나 화면 면적이 정확히 80%라는 뜻은 아니다. 카메라가 돌아갔다고 시간 기반 주도색을 다시 선택하지 않는다.

재생/정지·스크럽·PNG·MP4는 같은 절대시간 평가를 쓴다. 끝에 도달하면 처음부터 반복하며 사용자가 일시정지하면 멈춘다. 자동 층 수 변조는 별도 구현하지 않았지만 소수 층 수는 API나 추후 타임라인으로 보간할 수 있다.

### 25엑시스 전환의 축 강조

`IdentityAxisAccent.ts`는 기존 hold/dissolve 구간에 맞춘 단일 quintic envelope를 평가한다. `optical.frag.glsl`은 새 선이나 형상을 만들지 않고 기존 첫 번째 디멘션 윤곽의 굴절·Fresnel·등장 상태를 그대로 사용하며, 좁은 광학 코어에만 잠깐 백색 키라이트를 보탠다. 디멘션 등장 순서·스태거·카메라·기존 전환 시간은 변경하지 않는다. 강조는 한 루프마다 한 번이며 재생·스크럽·PNG·MP4 모두 같은 절대시간 값이다. 전환을 끄거나 `축 강조 강도`를 0으로 두면 강조도 꺼진다. 런타임의 `motion.identityTransition.axisAccent`에서 세기·진행률·구간을 확인할 수 있다.

## PNG 출력과 품질

- 미리보기는 재생 중 긴 변 최대 1280px, 정지 시 최대 1920px이다. PNG와 MP4는 이 버퍼를 확대하지 않고 요청 해상도로 따로 렌더링한다.
- `zoom > 2.4`에서는 같은 프레임의 2×2 공간 샘플링을 사용한다. 이전 모션 프레임을 섞는 방식이 아니다.
- UI PNG는 긴 변 3840px: 1:1=3840², 4:5=3072×3840, 9:16=2160×3840, 16:9=3840×2160.
- `OpticalFrameCapture`가 가드 타일과 4×4(16개) 공간 샘플을 선형 HDR에서 평균한다. Canvas2D는 최종 픽셀의 방향과 타일 연결만 담당한다.
- `capture(width,height,samples)`는 최대 8192px/34MP까지 지원하며 더 큰 출력은 명시적으로 거부한다. API 기본 샘플은 4개다.
- 슈퍼샘플 수는 Monte Carlo 패스 트레이싱 SPP와 다르다. 무작위 노이즈가 없어도 유한 해상도의 가는 반사광 윤곽은 앨리어싱될 수 있다.
- PNG는 불투명 검은 배경, 8bit sRGB이다. 현재 엔진의 PPI 메타데이터/인쇄판형·알파 출력·PNG 시퀀스 UI는 구현하지 않았다.

## 4K MP4 영상 출력

`출력`에서 긴 변 3840/1920px, 24/30/60fps, 공간 샘플 4/16개를 선택한다. 설정은 자동 저장한다. `4K MP4 저장`은 현재 판형·카메라·모션 복사본으로 0초부터 재생 길이까지 계산한다. 실제 픽셀 크기는 위 PNG와 같은 판형 기준이며 스크린 녹화나 업스케일링이 아니다.

- `OpticalFrameCapture`는 PNG·MP4가 공유한다. 한 영상에서 GPU 컨텍스트 하나, 재사용 CPU 프레임과 타일을 사용하고 타일 사이에서 진행률·취소를 처리한다.
- `OpticalVideoExporter`는 mediabunny/WebCodecs를 필요할 때만 불러온다. `start + frame / fps`로 평가하고 끝점은 제외한다. 각 프레임 추가를 기다려 인코더·디스크 적체를 제한한다.
- 실제 크기·fps 지원을 먼저 확인한다. H.264가 거부되는 세로/정방형 4K는 같은 해상도의 HEVC Main8 MP4를 확인해 사용하고, 모두 미지원이면 자동 축소 대신 오류를 표시한다. 코덱은 파일명과 결과에 기록하며 HEVC 지원 플레이어가 필요하다.
- 출력은 불투명 8bit sRGB, 무음, 손실 압축 MP4다. UHD/30fps 기준 60Mbps 목표에서 실제 픽셀·fps에 비례한다. 미세 윤곽·어두운 그라데이션의 압축 차이가 완전히 없어지는 것은 아니다.
- OPFS 임시 디스크로 스트리밍한다. 사용할 수 없으면 예측 용량과 실제 출력 모두 256MiB로 제한한 메모리 경로를 사용한다. 브라우저 재시작 후 렌더 재개는 지원하지 않는다.
- 내보내기 중 편집·중복 저장을 잠그고, 성공·취소·실패 후 GPU 자원과 잠금을 해제하여 원래 시간/재생 여부를 복원한다. 다른 세팅으로 바꾸려면 먼저 취소한다.
- API: `window.__pleosOptical.exportVideo({width,height,fps,samples,start,end}, download)`. 기본은 전체 구간과 패널 값이다. `download=false`는 10분간 유효한 Blob URL과 메타데이터를 반환한다. `cancelVideo()`로 중단한다. UI는 전체 구간, 부분 구간은 API로 지원한다.

## Legacy / reference only

초기 OpticalStudio의 전체 유리 외피 추적 함수는 남아 있지만, 현재 활성 진입점은 표면 반사를 제외한 가상 디멘션 이미지다. 자체 발광 실험의 `dimensionEmission.glsl`은 현재 소스에서 제거했으며 로컬 보관본 `saved-20260915090434072`에서만 확인한다. Instagram 및 큐브 이미지는 무드 참고 자료이며 전체 물리 시뮬레이션의 증거가 아니다.

- 현재 반사 표현의 복구 기준: 자체 발광 직전 로컬 저장본 `saved-20260915085224893`. 원본을 덮어쓰지 않으며, 복구본에는 전환 중 축 강조와 이후 출력 기능이 유지된다.
- 이전 멀티모드 앱: `?renderer=studio`; 그 밖의 `?renderer=raw`, `?renderer=legacy`는 참조 경로다.
- **플레오스 디멘션 초안**: `../pleos-snapshots/pleos-dimension-draft-20260910-155444/`는 불변 보관본이다.
- 이전 전체 소스/설정 백업 `../pleos-snapshots/pre-optical-rebuild-90RqWD/project.tar.gz`도 유지한다. Git, node_modules, dist, tmp, 이전 대형 artifacts는 제외한 백업이다.
- `public/versions/`의 로컬 빌드는 Git에서 제외된다. 로컬 저장본이 곧 GitHub 백업이라는 뜻은 아니다.
- 기존 `ior`, `bounces`, RGB 수치와 이름별 저장값은 삭제하지 않는다. 현 표현의 새 의미로 수치를 초기화하지 않는다.

## 검증과 handoff

`npm run verify`는 현재 기본 앱과 geometry contract를 검증한다. `npm run verify:legacy`는 이전 전체 체인이며 현재 엔진 PASS와 구분한다. 실제 실행 결과는 artifacts의 검증 보고서와 `artifacts/latest/runtime-state.json`에 기록한다. 완료 후 `npm run handoff:full`로 현재 런타임·문서·세 판형 이미지를 갱신하며 자동 commit/push는 하지 않는다.

- `verify:optical-geometry`: Axis 중심·각도·세 큐브 관계와 베벨 접점.
- `verify:optical-dimensions`: 영역별 층·간격, 코어/확산, 저장, 샘플·가드 타일 일치. 물리 정답과의 비교는 아니다.
- `verify:optical-light-cycle`: RGB 가중치·연속성·루프·단일색 복귀·저장·패널. 정확한 화면 색 점유율 보장은 아니다.
- `verify:optical-video`: 짧은 실제 4K MP4 크기·프레임 수·디코딩, 동일 시점 PNG 비교, 취소·실패 복구·패널. 전체 길이 장시간 렌더 안정성을 보증하지 않는다.

이 문서의 검증 목록은 실행 가능한 검증의 역할이다. 이번 실행의 PASS 여부는 생성된 보고서를 확인해야 한다.
